1. Visão geral

1.1 Problema

Academias pequenas controlam alunos, treinos e pagamentos em caderno ou planilha: dados se perdem, inadimplentes passam na porta e o dono não sabe quanto entra por mês.

1.2 Solução

O NOCTIS centraliza matrícula, check-in com validação de pagamento, financeiro e (na Fase 4) o módulo nutricional em um painel web que roda no navegador, publicado gratuitamente no GitHub Pages.

1.3 Objetivos do MVP

  • Cadastrar alunos com plano, status e situação da mensalidade.
  • Liberar o acesso apenas para alunos ativos e adimplentes.
  • Gerenciar mensalidades e estimar a receita mensal.
  • Estruturar as telas do módulo nutricional para a Fase 4.

3. Arquitetura e tecnologias

HTML + CSS + JS puro, Chart.js via CDN, localStorage, GitHub Pages. Arquitetura em 3 camadas:

CamadaArquivoPapel
Dadosjs/store.jsUsuários, seed inicial, leitura/escrita no localStorage
Lógicajs/app.jsLogin, CRUD, check-in validado, financeiro, nutrição, gráficos
Apresentaçãoindex.html + css/style.css7 telas em SPA por abas, tema NOCTIS
Não há build nem servidor: qualquer push na branch main entra no ar pelo Pages em 1–2 minutos.

5. Regras de negócio

  • RN01 — Check-in: acesso liberado somente se status = Ativo E mensalidade = Paga. Caso contrário, acesso negado com o motivo em tela.
  • RN02 — Receita: soma dos valores dos planos (Mensal R$ 89,90 · Trimestral R$ 239,90 · Anual R$ 799,90) dos alunos ativos com mensalidade Paga; pendentes compõem o "a receber".
  • RN03 — Perfis: Administrador vê tudo; Funcionário vê matrícula, check-in e financeiro; Aluno vê apenas o próprio Dashboard do Aluno.
  • RN04 — Cardápio: modelo ilustrativo por objetivo (Hipertrofia, Emagrecimento, Manutenção); prescrição real exige nutricionista.
